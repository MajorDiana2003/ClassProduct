# ClassProduct 🐍

Учебный проект интерактивного каталога продуктов с категориями, созданный в рамках изучения объектно-ориентированного программирования (ООП) на Python.

## 🚀 Стек технологий и зависимости

### Основное окружение:
* **Python** ^3.12 — интерпретатор языка.

### Инструменты разработки и качества кода (Dev-зависимости):
* **Poetry** — современный менеджер пакетов и виртуальных окружений.
* **Pytest** (^8.0.0) — фреймворк для написания и запуска автоматических тестов.
* **Pytest-cov** (^5.0.0) — плагин для анализа и вывода процента покрытия кода тестами.
* **Black** (^24.0.0) — автоматический форматировщик кода (настроен на длину строки 119 символов).
* **Flake8** (^7.0.0) — линтер для статического анализа кода и проверки соответствия PEP 8.
* **Mypy** (^1.8.0) — инструмент для строгой проверки аннотаций типов данных.


## Новые фичи (Домашнее задание 16.2)

В рамках этого этапа архитектура проекта была переведена на принципы абстракции и множественного наследования.

* **Инкапсуляция данных:** Списки продуктов (`__products`) и цены (`__price`) сделаны приватными для защиты от прямого изменения извне.
* **Методы-свойства (Getters/Setters):**
  * Геттер `products` в классе `Category` возвращает отформатированный список строк вида: `Название продукта, X руб. Остаток: X шт.`
  * Геттер и сеттер `price` в классе `Product` контролируют изменение стоимости (запрет на цены $\leq 0$ и интерактивное подтверждение снижения цены через `input()`).
* **Фабричные методы:** Реализован метод класса `new_product` для генерации объектов из словаря с автоматическим объединением дубликатов (складывание количества и выбор максимальной цены).
* **Магические методы (`__str__`, `__add__`):**
  * Класс `Product`: реализовано строковое представление в формате `Название продукта, X руб. Остаток: X шт.`, а также метод `__add__` для сложения общей стоимости товаров двух продуктов на складе (с валидацией типов).
  * Класс `Category`: реализовано строковое представление вида `Название категории, количество продуктов: X шт.` (суммирует количество всех единиц товара в категории).
* **Итерирование объектов (`CategoryIterator`):**
  * Создан вспомогательный класс-итератор для поочередного перебора объектов продуктов внутри категории в циклах `for`.
* **Логирование:**
  * Интегрировано логирование ключевых бизнес-процессов: инициализации объектов, добавления продуктов, выполнения арифметических операций и работы итератора.
В проект добавлена иерархия классов, а также усилен контроль типов при выполнении операций:

### 1. Наследование и расширение атрибутов
* Созданы два специализированных класса-наследника, расширяющие базовый класс `Product`:
  * **`Smartphone` (Смартфоны)**: добавлены уникальные характеристики: производительность (`efficiency`), модель (`model`), объем встроенной памяти (`memory`) и цвет (`color`).
  * **`LawnGrass` (Газонная трава)**: добавлены уникальные характеристики: страна-производитель (`country`), срок прорастания (`germination_period`) и цвет (`color`).

### 1. Абстрактные базовые классы (ABC)
* Создан абстрактный класс `BaseProduct`, задающий обязательные интерфейсы для всех продуктов (`__str__` и `__add__`).
* Создан абстрактный класс `AbstractStorage`, регламентирующий наличие геттера `products` для любых складских объектов (категории, заказы).

### 2. Применение миксинов (Mixin)
* Реализован класс-миксин `PrintMixin`. Он автоматически логирует в консоль информацию о каждом созданном объекте с помощью метода `__repr__` (вывод в формате `ClassName('Имя', 'Описание', Цена, Количество)`).

### 3. Новый функционал
* Добавлен класс `Order` (Заказ), наследующий `AbstractStorage`, который позволяет оформлять заказ на покупку определенного товара с автоматическим расчетом итоговой стоимости.

### 2. Строгие ограничения операций и валидация
* **Ограничение сложения (`__add__`)**: логика метода переработана с использованием функции `type()`. Сложение общей стоимости на складе теперь разрешено строго для объектов одного и того же класса. Попытка сложить смартфон с газонной травой вызывает исключение `TypeError`.
* **Ограничение добавления продуктов в `Category`**: в метод `add_product` добавлена проверка с помощью функции `isinstance()`. В список продуктов категории теперь можно добавить только сам `Product` или его наследников (`Smartphone`, `LawnGrass`). Любые сторонние типы данных вызывают `TypeError`.

## Новые фичи (Домашнее задание 17.1)

В рамках этого этапа в проект была внедрена развитая система обработки исключений, контроля данных и расчёта метрик:

### 1. Кастомные исключения и валидация данных
* Создано пользовательское исключение **`ZeroQuantityError`** (наследник класса `ValueError`), которое сигнализирует о попытке создания или добавления товара с нулевым количеством.
* В конструктор базового класса `Product` добавлена строгая проверка: если передано нулевое количество товара, выполнение программы прерывается выбрасыванием ошибки `ZeroQuantityError`.

### 2. Контроль логики с помощью блоков `else` и `finally`
* В методе `add_product` класса `Category` реализована комплексная конструкция `try-except-else-finally`:
  * Блок `try` проверяет тип данных и количество продукта.
  * Блок `else` срабатывает только при успешной валидации, добавляя товар в категорию и выводя уведомление: *«Товар 'имя' успешно добавлен»*.
  * Блок `finally` выполняется гарантированно при любом исходе операции, выводя системное сообщение: *«Обработка добавления товара завершена»*.
* Аналогичная отказоустойчивая логика `try-else-finally` интегрирована в процесс инициализации и оформления класса `Order` (Заказ).

### 3. Расчёт метрик и защита от деления на ноль
* В класс `Category` добавлен метод **`middle_price()`**, рассчитывающий средний ценник всех товаров в текущей категории.
* Метод защищён блоком `try-except` от критической ошибки **`ZeroDivisionError`**. Если в категории нет товаров, деление на ноль перехватывается, программа не падает, а метод корректно возвращает `0.0`.


## 📁 Структура проекта
* `src/models.py` — базовые доменные модели `Product` (продукт) и `Category` (категория) с логированием инициализации.
* `src/utils.py` — утилита для автоматического парсинга исходных данных из формата JSON в объекты классов Python.
* `data/products.json` — исходный файл с данными по категориям и товарам.
* `tests/` — изолированный пакет с автоматическими тестами и фикстурами.
* `main.py` — корневая точка входа для демонстрации работы скрипта.
